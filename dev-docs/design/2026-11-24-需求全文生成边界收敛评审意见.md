# 需求全文生成边界收敛评审意见（第 5 轮）

> 日期：2026-11-24
> 被评审文档：`dev-docs/planning/2026-11-24-需求全文生成执行计划.md`（v3）、`dev-docs/design/2026-11-24-需求全文生成与变体差异标注.md`（v1.2）、`dev-docs/planning/2026-11-24-需求全文生成v1.3修订清单.md`（v3）
> 处理结论：撤销「原子需求覆盖作为前置依赖」，边界冻结为两条独立工作流；两份文档与修订清单同步。

## 一、问题：两条工作流的边界被逐渐混在一起

`2026-11-24-RuleStudio需求覆盖与补齐.md` v1.1 修订记录明确区分了两条支线：

- **A 线：规则结构化** —— 原始资料 → 规则卡 / 配置项 / 未决项 → `rulebook/specs/`
- **B 线：原子需求提取与覆盖** —— 原始资料 → 原子需求（需求 ID、原文位置、证据）→ 需求登记表 → 需求 × 规则卡覆盖分析（六态）

两条线在「需求覆盖分析」处汇合，但输入、产物、工作流各自独立。原设计 I-21 / AD-14 还明确了一条原则：

> B 线必须直接读取 `rulebook/sources/`，不能从 A 线已生成的规则卡反推原子需求；否则 A 线漏掉的规则永远发现不了。

这条原则是为了保证 B 线的独立性，**不是**为了让 A 线的交付依赖 B 线。

### 合并是怎么发生的

| 时间 / 版本 | 变化 |
| --- | --- |
| 主需求 v1.7 | 明确结构化优先，原子需求覆盖属后续阶段 |
| 主需求 v1.8 | 新增需求全文生成，并把需求覆盖定义为「上游质量门」 |
| 全文生成设计 v1.2 | Document Block 增加 `requirement_refs`，接入原子需求 |
| 执行计划 v1 / v3 | P0-A 开始要求建立 2.3.3 原子需求登记表；上一轮又被建议成 R0 前置阶段 |

### 被绑在一起的两个质量目标

1. 规则结构化结果是否完整地转换成了需求文档？
2. 原始资料中的需求是否已经完整地结构化？

这两个问题不是一回事。把 (2) 作为 (1) 的阻塞条件，会让「结构化 → 文档」这条线卡在另一条尚未开始的工作流上。

## 二、结论：撤销前置依赖，冻结两条线边界

| 维度 | 需求全文生成（本文档线） | 原子需求覆盖（另一条线） |
| --- | --- | --- |
| 输入 | 已结构化规则、配置、未决项 | 原始 `rulebook/sources/` |
| 核心任务 | 按对局流程组织完整需求 | 独立提取原子需求 |
| 核心资产 | Document Template、Block、章节映射 | Requirement Registry |
| 核心验证 | 规则卡与配置项是否完整落入文档 | 原文需求是否被识别与覆盖 |
| 输出 | 完整需求文档 | 需求覆盖报告、缺口补齐清单 |
| 是否依赖另一条线 | **不依赖原子需求提取** | 需要规则结构化结果参与映射 |

### 当前线路的正确工作流

```text
输入：Rule KB（61 张杭州卡、25 项配置、未决项）
  Stage 1 编译有效规则集（继承 / 变体 / 配置合并）
  Stage 2 章节映射与文档组织（按实际对局流程）
  Stage 3 生成 Document Block（规则引用、配置引用、原文证据、确定性计算结果）
  Stage 4 来源与变体标记
  Stage 5 完整性验证（规则卡覆盖、配置覆盖、未决标记、公式正确性、来源追溯、章节映射完整性）
  Stage 6 输出（Document JSON + Markdown + Validation Report）
```

`source_evidence_refs` 仍然保留：规则卡自身就带原始资料来源，这是来源追溯，不等于重新执行原子需求提取。

## 四、建议冻结的最终决策

1. 当前开发线路只负责「结构化规则 → 完整需求文档」。
2. 不开发原子需求提取，不建立 Requirement Registry。
3. 不把原子需求覆盖作为 P0-A / P0-B 的阻塞条件。
4. 当前完整性以规则卡、配置项、未决项与文档结构为依据。
5. 原子需求提取与覆盖保留为独立工作流。
6. 未来通过可选的 `requirement_refs` 连接两条线，增强来源完整性验证，但互不侵入。

### 两个必须区分的概念

- **完整需求文档**：当前 Rule KB 中已结构化的规则与配置，完整地转化成了文档。这是本项目的交付目标。
- **原始需求的完整覆盖**：原始资料中的要求没有被结构化过程遗漏。这是另一条质量保障线的目标。
