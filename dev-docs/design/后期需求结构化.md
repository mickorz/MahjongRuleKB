## 一、需求结构化

面对产运，让他们把差异点整理成结构化表达。基线是杭州麻将；玩法差异只写和基线不一样的部分。



### 对话里要提醒

- 差异碰到核心功能时，点出影响面，避免基座行为被悄悄改掉。
- 对话里已经拍板的决定，写进对应条目，不留在聊天记录里。



### 写法上不要

- 同一条规则散落在多处。
- 一句话里塞进多个功能点。
- 交互只写「可以操作」，触发、控件、允许和禁止、反馈都没写清。
- 原有功能是改动还是新增，说不明白。



### 建议口径

沿用现有萧山结构化写法。差异只写三种：沿用、修改、新增。同一条规则一个编号，别的卡片只引用，不把判定抄进界面、不把公式抄进时序。


| **现在的问题** | **结构化里怎么落**                       |
| :--------- | :--------------------------------- |
| 规则散落各处    | 一条规则一个编号。配置、判定、时序、算分、界面分开写。       |
| 一句话很多功能点  | 每个槽只写本槽的内容。配置写取值，判定写条件，界面写看见什么。   |
| 交互描述不清楚   | 界面交互写清：触发、控件、允许、禁止、同一次其余操作、反馈文案。  |
| 改动和新增说不明白 | 每一行先标差异：沿用、修改、新增。修改和新增要写出基线现在怎么做。 |
