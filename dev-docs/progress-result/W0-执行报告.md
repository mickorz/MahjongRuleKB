## 三、过程中发现并修复的真实问题

### 1. 生成入口绕过权限矩阵（A 批次）

`run-p0b` / `run-p1` 原本直接 `writeFileSync` 落盘。这意味着变体隔离规则若不改这两个入口，只在单测里成立，真实生成路径仍可写任意变体。

修复：新增 `writeStageArtifact`，`documents/` 下的输出必过 `assertVariantScoped`；临时目录输出不强制（测试需要写 tmp）。

### 2. 三处 Error 类的 TS 参数属性破坏 `node` 直跑（A、C 批次）

`registry.ts`、`change/manager.ts`、`paths/fs-guard.ts`、`transaction/apply.ts` 使用构造函数参数属性，`node --experimental-strip-types` 直跑会 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。

A 批次只修了 `registry.ts`（因为 pipeline 要引用它），C 批次在真正跑 Change Manager 时发现 `manager.ts` 同样问题，遂一并修复四处。

**这不是洁癖**：CLI 入口不能引用权限模块、不能创建 Change，本身就是架构缺陷。

### 3. `invalidateOnEdit` 的失效粒度写错了（B 批次）

初版把全部审查记录一起置为失效。测试「改第 3 章后第 5 章仍应 reviewed」直接失败。

正确规则：**所有记录随文档版本前进，只有被编辑目标及其上级退回 `unreviewed`**。否则改任何一处都会废掉整篇审查结论，与「不做逐段确认」的产品原则冲突。
