## 3. 过程中修掉的问题

| # | 问题 | 修法 |
|---|---|---|
1 | `git worktree add ../../...` 相对路径按**参考仓库根**解析，跑到 `E:/dev-examples` | 一律用绝对路径 |
2 | Windows 上 Vite `resolve.alias` 把 `E:\...` 当相对路径拼成 `./E:\...` | 改 `resolveId` 插件 + `replaceAll("\\", "/")` |
3 | worktree 检出为 CRLF，patch 锚点（LF 写法）匹配不上 | patch 前归一为 LF、写回时还原 |
4 | 入口文件放在 `vendor/` 下，向上找不到 `node_modules`（react 解析失败） | 构建时把入口暂存到 worktree 内 `.xc-chat/`，build 后清理 |
5 | 模板字符串里写正则，反斜杠被吃掉导致生成的 vite 配置语法错误 | `resolveId` 里改用 `endsWith` 判断，不用正则 |
6 | `mountChat` 重复调用在同一宿主上建多个 React root，导致后续 `applyTurns` 落到失效 root | `WeakMap<HTMLElement, ChatHandle>` 保证一宿主一 root，重复 mount 等于 applyTurns |
7 | 轻量 markdown 在 `for..of` 里 `splice` 输入数组 → 死循环，整棵 React 树被卸载（页面空白、无报错） | 改为下标推进、不改输入；补表格支持 |
8 | 旧会话数据里 `tools` 是字符串数组（新代码按对象读） | payload 兼容两种形态 |

## 4. 第二轮：五项差距全部收口

| # | 原差距 | 处理方式 |
|---|---|---|
1 | 「工作了 0 秒」 | 消息记录 `at`（响应时刻）+ `ms`（实测耗时），payload 在该区间内均分步骤时间戳；亚秒级/无时间戳会话显示「已完成」 |
2 | 工具摘要英文名 | `patches/work-item-labels.mjs` 注入六个工具中文名 + 改写中文模板 |
3 | Composer 未替换 | bundle 新增 `mountComposer()`（参考项目 `.composer`/`.prompt-box` 外壳），工作台隐藏内置输入区 |
4 | 深色主题 | 覆盖层按参考项目变量名重写纸色令牌，并修掉写死的深色值（标题/代码/链接/用户气泡） |
5 | 产物不入库 | `server/chat-widget/` 入库（720KB）；`npm run build:chat-widget` 重建；页面用产物 mtime 做版本号避免旧缓存 |

顺带补掉的三个渲染缺口：

- 样式子集漏抽 16 个消息类前缀（`.user-message*` / `.assistant-response*` / `.thinking-*` 等）→ 复制按钮裸成灰方块、气泡无底色；补齐后 CSS 30KB → 48.5KB（gzip 9.3KB）
- 覆盖样式排在 `<link>` 之前被盖回去 → 改为始终最后 append
- 轻量 markdown 无标题支持，`##` 原样露出 → 补 `#`~`####`

### 4.1 加载阻塞（本轮踩到的第 9 个坑）

症状：页面打开助手后长时间空白，`import("/chat-widget/chat-lib.js?v=…")` 请求一直 pending、
CDP 评测随机超时；curl 同一 URL 却是 200。

根因：666KB 未压缩产物走 chunked 编码，浏览器侧读这段响应被卡住，同一 URL 的后续 import
全部排队等这次请求 → 整块不加载。而 `cache-control: no-store` 又让每次打开都重下 666KB。

修法：`/chat-widget/*` 路由改为按 `Accept-Encoding` gzip（666KB → 175KB）+ 显式 content-length
+ 长缓存（URL 自带 mtime 版本号）。加载时间从「卡死」变成 2 秒内出现。

顺带补的健壮性：加载/渲染失败一次就置 `widgetBroken`，自动回退内置渲染，
不会留一个空白面板。
