# W3-4 / W4-3 执行报告：HTTP 写接口与最小编辑能力

> 完成日期：2026-11-25｜结论：**通过**（端到端手工验证 + 9 条自动化用例）

## 交付

| 接口 | 行为 |
| --- | --- |
| `POST /api/proposal` | 服务端权限复验 → 转 `DocumentProposalInput` → 返回 `before` / `after` / `base_revision`；**不写盘** |
| `POST /api/apply` | 一批 mutation → 建会话 → 全或无应用（Transaction）→ 返回版本前后与审查失效数 |
| `POST /api/review` | 写一条审查记录（actor=`server`，intent=`apply-review`），返回整份文件与汇总 |
| `GET /api/reviews/:variant` | 文档级 + 各章节审查状态汇总 |

服务端实现：`server/app.ts`（`handleWrite` 统一入口）、`studio/review/store.ts`（审查记录读写）。

前端（无构建）：可编辑片段用 `contenteditable`（仅 `modified` / `added`）；顶部工具条显示改动数、预览、应用、清空；预览逐条调用 `/api/proposal` 展示改动前后与基线版本；`apply` 成功后清空草稿并重载；章节旁「标为已审」调用 `/api/review`。

## 安全（评审 P1-5 全项）

| 项 | 实现 | 用例 |
| --- | --- | --- |
| CSRF | 写请求必须带 `X-Rule-Studio: 1` | 缺头 → 403 |
| Origin | 给了就必须同源 | 跨源 → 403 |
| Host | 精确匹配白名单 | 伪造 → 403 |
| 权限复验 | 服务端重跑 `checkMutation` | 继承片段 → 403 |
| 方法限制 | 非 GET/POST → 405 | PUT/DELETE → 405 |

## 端到端手工验证

```
1) 取可编辑片段      → SEG-000105
2) 预览              → ok:true，before 有内容，after 为新文本，基线版本 0
3) 无 CSRF 调 apply  → 403
4) 带 CSRF 调 apply  → ok:true，applied 1，版本 0 → 1
5) 标记章节已审      → 200，RVW-0001
6) GET /api/reviews  → opening: reviewed，document: unreviewed
```
