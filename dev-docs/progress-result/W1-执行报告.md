## 五、过程中修正的两类问题

### 1. 检查器缺陷（3 处）

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| `136张` 判为无来源 | 配置值只有 `136`，与带单位 token 不相等 | 数字核心匹配（去单位）+ 数字边界校验（防 `8` 命中 `800`） |
| `21 张` 判为无来源 | 该数值写在配置项 `description` 而非 `value` | 配置来源改为 value + description 合并 |
| 覆盖 60/61 | prompt 未要求逐卡引用 | prompt 增硬性要求「每张卡 / 每个配置至少被引用一次」 |

### 2. 出题缺陷（2 处，比检查器缺陷更值得记）

初版 RQ-009 问「杠分怎么算」、RQ-011 问「流局杠分为 0」。核对规则卡发现：

```
grep -rn "杠分" rulebook/specs/base/hangzhou/
→ 仅 HJ-F-YUANYING-PEIFEN 一行：「杠分不在此公式内」
```

**杭州没有杠分算法，也没有「流局杠分」概念 —— 那是萧山 `XS-F-HUPAI-GANGFEN` 的内容。** 我按萧山文档的印象出题，却拿杭州知识库验收，会把"题目错了"误判成"文档漏了"。

两题已按杭州卡实际内容重写（RQ-009 只考番型档位与杠计面子；RQ-011 只考流局时机与计局），并在 YAML 头部写明出题约束：**每个 expected_point 必须能在一张杭州规则卡或配置项里找到依据**。
