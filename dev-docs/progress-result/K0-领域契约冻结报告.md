## 二、K0 期间确立的关键约束

1. **Agent 输入与可信记录分离**：`ProposalInput` 用 `.strict()` 拒绝路径、版本基线、Hash 与状态字段。
2. **版本事实源唯一**：`document.json` 顶层 `document_version`；Block 上的同名字段只是快照。
3. **写入主体按路径授权**：Agent 无直接写权限；Stage / Transaction / Archive / Compiler 各自白名单，intent 精确到文件名。
4. **路径安全不只靠 `endsWith`**：先 `normalizeRelative` 再 `realpathSync`，拒绝绝对路径、`..`、反斜杠、符号链接逃逸。
5. **事务顺序固定**：取锁 → 双校验 → 备份核对 → writing 逐文件复查 → 临时文件 rename → 写入后校验 → committed。
6. **失败不静默**：回滚失败标记 `recovery_failed` 并保留现场，不自动重试。
7. **身份匹配不用文本相似度**：只依据 `logical_block_id`、章节、引用锚点与序号；序号兜底仅在一对一时启用。
8. **未匹配的人工修改进入失效待处理**，不自动迁移。

## 六、类别说明

K0 交付的是**可被代码验证的工程契约**，不是功能实现：没有 Stage 生成、没有 Change Manager、没有 UI。任何在 P0-A 期间发现的契约缺口，须以「K0 补丁」方式单独修正，不得在生成流程里就地绕过 Schema 或权限矩阵。
