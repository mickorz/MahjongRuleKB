### K0-3 事务契约与提交（2026-11-24）

新增 `studio/transaction/`：

| 文件 | 内容 |
| --- | --- |
| `journal.ts` | 两套状态机分离：Proposal `draft→ready→approved→applied`（另有 rejected/stale/failed）与 Transaction `preparing→prepared→writing→committed/rolled_back/recovery_failed`；非法迁移抛 `TxStateError`；事务清单 Schema（含 `existed_before` / `original_sha256` / `new_sha256` 一致性校验、路径去重） |

关键约束：
- 顺序固定为「取锁 → 校验 → 备份 → 写入」，不允许先校验后取锁

- 恢复：`preparing`/`prepared` 未写入任何文件→丢弃；`writing`→按 originals 回滚，备份缺失或 Hash 不符→`recovery_failed` 并保留现场、不自动重试

### 差异确认闭环（2026-11-24）

人工复核发现「修改 95 条、新增 136 条全部带『差异待确认』」。查下来的根因不是标签写错，而是**确认动作从来不存在**：生成器硬编码 `candidate`，`changes.json` 也硬编码，全仓库没有任何路径能把状态改成 `confirmed`。标记永远亮着，信息量为零。

另有一层语义澄清：变体卡的 `change_type` 是作者写在 front matter 里的，不是机器比对出来的。所以 `diff_status` 从来不是「AI 猜的候选差异」，而是「人工还没签的工单」。

| 交付 | 内容 |
| --- | --- |
| `studio/pipeline/diff-review.ts` | 人工审核输入：`confirmed_rules` / `confirmed_segments`，Zod 校验，文件不存在等于一条没确认 |
| `generate-variant.ts` | 命中审核清单的 `modified` / `added` 片段升为 `confirmed`，未命中的保持 `candidate` |
| `changes-json.ts` | 条目级 `diff_status` 同步，文档与索引不会打架 |
| `run-p1.ts` | 读 `documents/xiaoshan/diff-review.yaml`，输出「已人工确认 N 条」 |

实测：确认 2 张卡（1 修改 + 1 新增）后，9 个片段从 candidate 变 confirmed，标记消失；其余保持 221 处待确认（229 片段减 8... 精确值见测试）。测试 273 通过。

### 待评审分析：差异确认的必要性（2026-11-24）

规则方提出关键质疑：萧山差异文档已经给出差异，据此生成的卡片本就已确定，为何还要人工逐段确认。

分析结论（`dev-docs/design/2026-11-24-差异确认必要性分析.md`）：

- 逐段确认 229 段不可执行，等于审计剧场；`candidate` 作为「全量默认值」没有信息量
- 但检查并非多余，真实风险在结构化环节：改写丢槽位（R1）、新增实为重复表达（R2）、归类与溯源字段矛盾（R3）

### 离线快照点击失效的原因分析（2026-11-27）

规则方反馈：`offline.html` 样式正常，但左侧「世界观 / 角色表 / 故事规划」点击无效果。

分析结论写入 `dev-examples/style-capture/bishuxiezuo/ANALYSIS-why-clicks-do-nothing.md`，三层原因：

1. **快照移除了全部 JS** —— 原页面是空壳 HTML + React 运行时渲染，保留脚本会用虚拟 DOM 覆盖渲染结果并向后端拉数据，离线必败
2. **点击事件绑在 React 根上** —— 实测 `.pbi` 元素 `onclick === null`，无 `href`，靠根节点事件委托与内部状态
3. **这三个 tab 是向导步骤而非视图切换** —— 点击后 `.pbi` 数量变为 0、换成 `.cs-t` 步骤条，并发起「全员批量 · 1 次调用」的生成请求（服务端计算）

同时记录一条操作风险：分析过程中为观察 DOM 变化点击了「角色表」，**触发了一次真实生成请求**（页面显示"正在编织全员信念生态"）。已在文档中提示检查账号额度，并停止对线上页面做任何点击。

给出三条可选路线（多状态静态快照 / CDP 录制回放 + mock fetch / 完整镜像）与成本评估，结论：当前 `offline.html` 定位为**视觉参考**，交互请用在线站点。
