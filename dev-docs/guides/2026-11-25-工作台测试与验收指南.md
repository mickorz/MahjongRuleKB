# Rule Studio 工作台测试与验收指南

> 适用版本：W5 完成（2026-11-25，`npm test` 522 条）
>
> 用途：说明「怎么验证」这件事本身 —— 三层验证各验什么、怎么跑、当前可操作范围与已知限制。
>
> 读者：开发者与策划（策划只需看第三节「人工操作验收」）。

---

## 一、三层验证各管一件事

| 层 | 谁执行 | 证明什么 | 证明不了什么 |
| --- | --- | --- | --- |
| 自动化测试 | CI / `npm test` | 契约、权限、事务、合并、接口的逻辑正确 | 页面好不好用 |
| 脚本端到端 | 开发者（curl） | 真实服务上的读写链路通 | 信息够不够、别扭不别扭 |
| **人工操作验收** | **策划** | 能不能用、哪里别扭 | 大规模回归 |

关键一条：自动化测试全绿**不代表**界面可用。`人数：人数：4` 这个 bug 是人工看一眼发现的，522 条测试一条都没报。

## 二、自动化测试

### 2.3 值得单独记住的守卫

| 守卫 | 文件 | 防什么 |
| --- | --- | --- |
| 参数属性禁令 | `tests/studio/direct-run-guard.test.ts` | `node --experimental-strip-types` 直跑崩（已踩三次） |
| 基座双权限 | `tests/studio/paths/registry.test.ts` | 「人工不得编辑基座」与「Stage 可生成基座」两组独立断言 |

| 合并禁自动取边 | `tests/studio/pipeline/w5.test.ts` | 两边都变时静默覆盖人工修改 |

## 三、人工操作验收（策划做这一节就够）

### 3.1 启动

```bash
node studio/pipeline/run-w1.ts     # 生成杭州基座文档（首次或规则变更后）
node studio/pipeline/run-w2.ts     # 生成萧山变体文档（依赖基座）
node server/index.ts               # 默认 http://127.0.0.1:4173/
```

浏览器打开 `http://127.0.0.1:4173/`。

### 3.2 四步操作清单

| 步骤 | 操作 | 预期现象 |
| --- | --- | --- |
| 1 | 左侧点 `xiaoshan`，找橙色「修改」段落，在虚线框内改几个字，点别处失焦 | 顶部出现「编辑草稿 N 处改动」 |
| 2 | 点 [预览改动] | 显示「改动前 / 改动后」与基线版本号；被拒时给出原因 |
| 3 | 点 [应用] | 提示「已应用 N 处，文档版本 X → X+1」，页面重载 |
| 4 | 左侧章节旁点「标为已审」 | 右侧质量区刷新，审查状态变化 |

第 3 步之后，改动落在 `documents/xiaoshan/editorial-overrides.yaml`（表达层；`documents/` 已在 `.gitignore`，不会污染仓库）。

### 3.3 预期不可用的功能（不是故障）

| 现象 | 原因 |
| --- | --- |
| 蓝色「继承」/ 绿色「新增」段落无法编辑 | 继承内容只读是设计；新增段落虽可编辑，但本轮只验证修改段落链路 |
| 杭州文档整篇无法编辑 | 基座受保护，变更走重新生成流程 |
| 只有行内改字，没有加粗 / 列表 / 表格 | 富文本工具栏未做（D-02 未拍板） |
| 没有 Markdown 源码模式 | 同上 |
| 没有 AI 对话编辑入口 | 意图路由已就绪，UI 未接 |
| 右侧面板空白 | 仅在选中段落或存在告警时有内容 |
| 应用只支持改文本 | 移动段落 / 隐藏走结构提案，UI 未接 |

### 3.4 验收时重点感受什么

比找 bug 更有价值的三点：

1. 改一个字要不要滚半天找按钮（工具条是否够顺手）
2. 预览的信息够不够判断「该不该应用」
3. 右侧空白时，你希望它显示什么

## 四、脚本端到端（开发者用）

```bash
# 起服务后
curl -s http://127.0.0.1:4173/api/doc/xiaoshan | head -c 200

# 预览（不写盘）
curl -s -X POST http://127.0.0.1:4173/api/proposal \
  -H "content-type: application/json" -H "x-rule-studio: 1" \
  -d '{"variant":"xiaoshan","mutation":{"target":{"segment_id":"SEG-000105"},"op":"replace-text","text":"测试改动","source":"richtext","rationale":"验收"}}'

# 缺 CSRF 头应 403
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:4173/api/apply \
  -H "content-type: application/json" -d '{"variant":"xiaoshan","mutations":[]}'

# 应用
curl -s -X POST http://127.0.0.1:4173/api/apply \
  -H "content-type: application/json" -H "x-rule-studio: 1" \
  -d '{"variant":"xiaoshan","mutations":[{"target":{"segment_id":"SEG-000105"},"op":"replace-text","text":"测试改动","source":"richtext","rationale":"验收"}]}'

# 审查
curl -s -X POST http://127.0.0.1:4173/api/review \
  -H "content-type: application/json" -H "x-rule-studio: 1" \
  -d '{"variant":"xiaoshan","target":{"type":"section","id":"opening"},"status":"reviewed","reviewer":"策划"}'
curl -s http://127.0.0.1:4173/api/reviews/xiaoshan
```

## 五、已知薄弱点（测试层面）

| 项 | 说明 |
| --- | --- |
| 前端无自动化测试 | 内联 HTML + JS，没有 DOM 测试；UI 回归完全靠人工 |
| 服务端测试偶发超时 | 并行跑全量时 `tests/server` 曾出现一次握手超时，单独跑正常，未复现 |
| 检查器过拟合风险 | W1 的 4 轮调参均针对杭州文档；换萧山或改规则卡后可能暴露新缺陷 |
| R2 相似度阈值未校准 | 名称 0.85 / 正文 0.6 为拍定值，缺样本验证 |
| 阅读题库需随规则更新 | `tests/acceptance/reading-questions.yaml` 的 expected_points 必须能在杭州规则卡找到依据 |
