### B-6 文档提案数据契约（v3 修订：复用 `baseRevision` + 状态机分层）

| 项 | 内容 |
| --- | --- |
| 位置 | 五（产物目录）；十二；十五（新增 AD-38、AD-39）；十四（新增 FR-58、I-50）；十六（新增 AC-53、AC-54）；主需求文档 10.2 / 10.3 同步 |
| 问题 | ① B-6 v2 把 Proposal 状态机与 Transaction 状态机混成一套；② `basedOnDocumentHash` 与目标文件 Hash 不是一回事；③ 操作与目标文件对应关系缺失；④ 字段命名两套（camelCase 与 snake_case） |
| 改成 | 定义文档提案契约（下表），并明确：**Proposal 状态**（`draft` / `ready` / `approved` / `applied` / `rejected` / `stale` / `failed`，沿用主文档 10.2）与 **Transaction 状态**（`preparing` / `prepared` / `writing` / `committed` / `rolled_back` / `recovery_failed`，沿用 10.3）是**两层**：文档提案与规则提案共用 Proposal 状态机，应用时进入 Transaction；契约字段全篇统一 **camelCase**，沿用主文档 `baseRevision` |
| 验收 | 契约字段齐全；AC-53 分别验证版本冲突与文件 Hash 冲突；AC-54 验证 `status` 只取 Proposal 枚举值 |

文档提案结构（示意）：

```json
{
  "id": "DOC-P-001",
  "type": "document",
  "rulesetId": "xiaoshan-friends-4p",
  "targetVariant": "xiaoshan",
  "baseRevision": {
    "documentVersion": 3,
    "files": [
      { "path": "documents/xiaoshan/editorial-overrides.yaml", "sha256": "…" }
    ]
  },
  "target": {
    "blockId": "DOC-XS-000123",
    "segmentId": "SEG-000456"
  },
  "op": "append | replace-text | hide | move-block | edit-outline",
  "before": { "text": "…", "sha256": "…" },
  "after": { "text": "…", "sha256": "…" },
  "status": "ready"
}
```

| 必填字段 | 作用 | 校验 |
| --- | --- | --- |
| `type: document` | 与规则提案区分 | 提案加载时校验 |
| `targetVariant` | 目标变体 | 必须存在于规则集注册表 |
| `baseRevision.documentVersion` | 文档版本基线 | 应用前与当前 `document_version` 比对（I-36） |
| `baseRevision.files[]` | **每个将被修改文件的路径与 sha256** | 应用前逐文件重算比对；**任一不匹配即拒绝** |
| `target.blockId` / `target.segmentId` | 精确定位 | 块 / 片段必须存在 |
| `op` | 操作类型 | 必须与目标文件层级匹配（见下表） |
| `before` / `after` | 修改前后内容与各自 sha256 | 写入前逐文件复查 |
| `status` | Proposal 状态 | 只能取 Proposal 枚举；`applied` / `failed` 由 Transaction 结果回写 |

**操作与目标文件映射（目标路径由服务端推导，Agent 不得指定）**：

| `op` | 落点 | 目标文件（服务端推导） |
| --- | --- | --- |
| `append` / `replace-text` / `hide` | 文档表达层 | `documents/<variant>/editorial-overrides.yaml` |
| `move-block` / `edit-outline` | 章节映射层 | 章节映射文件（`document-outline` 落盘位置，由 Stage 2 产物路径决定） |

**两层状态机**：

| 对象 | 状态 | 职责 |
| --- | --- | --- |
| Proposal | `draft` / `ready` / `approved` / `applied` / `rejected` / `stale` / `failed` | 用户审批与提案生命周期 |
| Transaction | `preparing` / `prepared` / `writing` / `committed` / `rolled_back` / `recovery_failed` | 文件写入、事务提交与崩溃恢复 |

文档提案与规则提案共用 Proposal 状态机；应用时进入 Transaction，事务结果回写 Proposal 状态（`committed` → `applied`，回滚 → `failed`），与主文档 10.3 的既有映射保持一致。
